# Educational Quiz Web Application using Django

#### Video Demo:  <URL HERE>

#### Description:
  This is a web-based quiz application built with Django, a popular web apps framework using Python,
  In my Project, users can make an account by a Register form, login to their account by Login form, or Logout,
  they also can take quizzes, with their results, and an optional AI feedback in order to understand questions more clearly whether they have an account or not, 
  Authenticated users have the ability of creating new quizzes and accessing a page that includes their scores in all submitted quizzes.
  Key features include:
  - User authentication (registration/login).
  - Interactive quiz-taking interface.
  - Real-time scoring and results.
  - Quiz creation (for Authenticated users).
  - Scores page (for Authenticated users).
  - Database storage for categories, quizzes, questions, answers, scores, and users.

  ##### File Structure Breakdown

  ###### Project Configuration Files
  1. **settings.py**
    - Containes global Djngo Configurations.
    - Defines installes apps, middleware, databases, templates, and static files.
    - Sets authentication backends and security settings.
    - Loads sensitive data from .env file like the API keys.

  2. **urls.py**(Project-Level)
    - Main URL routing configuration.
    - Maps URLs to app-specific views.
  
  ###### Quiz App Files
  1. **models.py**
    - Database schema definitions for:
      - `User` (Inherits from Django built-in AbstractUser)
      - `Category` (title, image)
      - `Quiz` (id automatically generated by UUID, owner foreign key, title, is_public, total_points, timestamp, category foregin key)
      - `Question` (quiz foreign key, content, points, image URL, timestamp)
      - `Answer` (question foreign key, content, is_correct, selected_by (user ManyToMany relation), timestamp)
      - `QuizScore` (quiz foreign key, user foreign key, points, timestamp)
    - Includes serializers for each model.
    - Includes a get_correct function that returns a dictionary of each question with the correct answer of it.
    - On saving the quiz it automatically calculates the total_points of the questions.

  2. **forms.py**
    - Defines form classes for:
      - Registration - A User ModelForm with an additional field for password_confirmation.
      - Login - Inherits from Django built-in AuthenticationForm.
      - Quiz - A Quiz ModelForm with three fields (title, is_public, category) and customizations.
      - Question - A Question ModelForm with three fields (content, points, image) and customizations.
      - Answer - An Answer ModelForm withe two fields (content, is_correct) with an additional field to keep track of the answer's question.
      - QuestionFormSet - Inherits from the QuestionForm and make a formset with a maximum of 50 questions.
      - AnswerFormSet - Inherits from the built-in BaseInlineFormSet with some additional error checking on calling the clean function.

  3. **utils.py**
    - Includes some helping functions:
      - `call_groq` - Takes a prompt parameter, then it sends a request to the Groq API and returns the response in markdown.
      - `convert_to_HTML` - takes a result (in markdown) parameter, then it converts the markdown content to raw HTML.
      - `map_question_answer` - takes a answer_formset_data as a parameter submitted from a user, then it returns a question_answer_mappings      (python dictionary) with each question index in the question_formset_data associated with a list of answers data of that question as value.  

  4. **views.py**
    - Handles business logic for:
      - `(register, login_view, logout_view)` - User Authentication handling
      - `index` - Renders the __index.html__ template.
      - `create_quiz`- Login required, on GET method, it displays a form that includes an object of the QuizForm, QuestionFormset, AnswerFormset
      on POST method, it checks if the data is valid:
        - if the data is valid, it does some logic to store the quiz associated with its questions and answers in the database. 
        - if it's not valid, it shows the form again with the submitted data, in addition to an error message of what's wrong.
      - `load_quizzes` - Takes a category_id as a parameter, then it returns a JSONResponse of all the quizzes that belongs to that category.
      - `view_categories` - Renders the __categories.html__ template with all the categories in the database.
      - `view_quiz` - Renders the __quiz.html__ template with the quiz data populated in it.
      - `quiz`- Takes a quiz_id as a parameter then it returns a JSONResponse that includes the serialized data of the quiz depending on:
        - if the user isn't authenticated, it creates the selected_answers and scores in the user's session and sets every question's selected answer intially to None if there isn't a previous answer and the checks if there's a previous score and pass it in the Response.
      - `update_answer` - Takes an answer_id as a parameter, it can be accessed only via PUT method then:
        - if the user is authenticated, it adds the user to the selected_by answer field in the database.
        - if the user isn't authenticated, it stores the answer in the selected_answers in the session.
      - `calculate_score` - It can only accessed via POST method, then it takes the data sent via JavaScript fetch, then:
        - if the user is authenticated, it calculates the score depending on the submitted answers, then it stores it in the database.
        - if the user isn't authenticated, it calculates the score depending on the submitted answers, then it stores it user's session.
      - `validate_code` - It can only accessed via POST method, then it takes the code submitted, checks if it's the code of the needed quiz:
        - if so, it redirects the user to the view_quiz route with the quiz_id as an argument.
        - if not, it send an error message saying that the code isn't for this quiz.
      - `ask_ai` - Takes a question_id as a parameter, then it calls the __call_groq__ function in the __utils.py__ with the content of the question as an argument, converts the API response to HTML by calling __convert_to_HTML__ function in the __utils.py__ then it sends the HTML as a response.
      - `view_scores` - Login required, Renders the __scores.html__ template with all the quizzes' scores of the user who sent the request.
  5. **admin.py**
      - Registers models with Django admin interface.
      - Customizes adimn panes display for quizzes, questions, answers, scores, and categories.

  6. **urls.py**(App-Level)
    - Defints app-specific routes:
      ###### Pages Routes:
        - `/` - Default route Includes a welcom page with two buttons to register or take quizzes.
        - `/register/` - Displays a registration form in order to make an account.
        - `/login/` - Displays a login form in order to login into your account.
        - `/logout/` - Logging out the users.
        - `/view_quiz/<uuid:quiz_id>` - Allows users to take quizzes in an interacive interface.
        - `/categories/` - Lists all the categories available allowing the users to click on a category to see its quizzes and take them.
        - `/create/` - Displays a quiz creation form in order to allow users to make new quizzes with qusetions and answers.
        - `/validate_code/` - When a user try to access a private quiz it checks the quiz code if it's true.
        - `view_scores` - Lists all the scores of the quizzes that user has already submitted.
      ###### API Routes:
        - `/load_quizzes/<int:category_id>` - Returns a JSON object of all quizzes of a specific category.
        - `/quiz/<uuid:quiz_id>` - Returns a JSON object of a quiz with all details by calling the serialize function in __models.py__.
        - `/update_answer/<int:answer_id>` - It can only accessed via PUT method to add an answer in the selected_answer of a user.
        - `/calculate_score/` - It can only accessed via POST method, it takes the selected_answers of a user and calculates the score of it.
        - `/ask_ai/<int:question_id>` - It sends a request to the Groq AI API with a prompt and gets a response.

  ###### Templates (`templates/`)
  1. **layout.html**
    - Includes the basic structure of all pages (a navbar with few links to navigate between app routes).
    - Includes a title block using Django templeting language.
    - Includes a body block to fill it in other templates.
  2. **index.html**
    - A simple structure of a welcome page.
  3. **register.html, login.html**
    - User authentication form.
    - Handles login/registraion UI.
  4. **create.html**
    - Includes a Quiz form with a question formset and an answer formset.
    - Includes some buttons to add/remove question/answer forms.
  5. **categories.html**
    - Includes two views:
      - `categories-view` - Lists all the categories with a button to explore its quizzes.
      - `quizzes-view` - Lists all the quizzes of a category based on the user click of a category button.
  6. **quiz.html**
    - Includes the main structure of the taking quiz page.
  7. **scores.html**
    - Lists all the scores of previously submitted quizzes by a user.

  ###### Static Files (`static/`)
  - CSS
    1. **quiz.css**
      - Custom syling for all templates in the app.
      - Responsive Design for mobile devices.
      - A few animations.
    2. **all.min.css**
      - The main file for fontawsome icons.
    3. **bootstrap.min.css**
      - The mini file that includes all bootstrap styling utilites and components.
  - JavaScript
    1. **quiz.js**
      - Handles client-side interactions of the __quiz.html__ template:
        - Intialize the quiz by populating the first question contents by sending a request using fetch to the `quiz` route.
        - Allowing users to navigate between questions with next/previous buttons.
        - Allowing users to select an answer then sends a request using fetch to the `update_answer` route.
        - Keeps track of the previous selection of the user.
        - Displays user-friendly badges of the unanswered question if the user tried to submit the quiz with unanswered question(s).
        - Allowing the user to submit the quiz by sending a request using fetch to the `calculate_score` route then it displays the result.
        - After submission, it displays user-friendly badges shows if the answer was correct on hovering/clicking on them.
        - Finally, if the user has submitted that quiz before it prevent him from altering answer, and displays its score.
    2. **create.js**
      - Handles client-side interactions of the __create.html__ template:
        - Handles the clicking on add question/answer button then it adds a question/answer form altering the needed indexes of the formset.
        - Handles the clicking on remove question/answer button then it removes a question/asnwer form altering the needed indexes of the formset.
        - Keeps track of mainpulating indexes that displayed to the user depending on removing/adding questions/answers.
        - Updates the formset management fields depending on removing/adding questions/answers.
    3. **categories.js**
      - Handles client-side interactions of the __categories.html__ template: 
        - Handles the clicking on explore button of a category then it displays all the quizzes the belongs to that category in the quizzes-view and hide the categories-view.
        - Handles the clicking on back button in the quizzes-view then it shows the categories-view again and hide the quizzes-view.
    4. **message.js**
      - Checks if there is a message in any view then it displays it with animation, after the message got animationend it hides it.
